# 2일차 3교시 실습 — 배열 값 처리와 경계 오류

## 이번 시간에 할 일

- 누적 변수의 **초기값**이 결과를 어떻게 바꾸는지 합계·곱셈·최댓값 세 경우로 확인합니다.
- `ArrayIndexOutOfBoundsException`을 일부러 재현하고 조건식으로 고칩니다.

## 실습 파일

- `chapter06/Factorial.java` / `MaxValue.java` / `SumOfOdds.java`
- `chapter05/ArraySum.java` (2교시에서 for문으로 고친 상태에서 이어서 사용)

## 미션

### 3-1. 곱셈의 시작값이 0이면
`Factorial`을 실행해 120을 확인합니다. `int answer = 1;`을 `int answer = 0;`으로 바꿔 실행하고 결과를 적은 뒤 되돌립니다.
→ 왜 0이 나오는지 한 줄로 적습니다. (곱셈의 시작값과 덧셈의 시작값은 왜 다를까요?)

### 3-2. 값이 쌓이는 과정을 들여다본다
`Factorial`의 반복 안에 다음을 넣어 1 → 2 → 6 → 24 → 120이 만들어지는 과정을 캡처합니다.

```java
System.out.printf("i=%d answer=%d%n", i, answer);
```

### 3-3. 평균이 4로 나오는 이유
`ArraySum`(for문 버전)에 평균 출력을 추가합니다. 먼저 `int avg = answer / arr.length;`로 출력하고, 다음에 `double avg2 = (double) answer / arr.length;`로 출력해 두 값을 비교합니다.
→ 4와 4.75가 갈린 이유를 타입으로 설명합니다.

### 3-4. 최댓값의 시작값을 잘못 잡으면
`MaxValue`를 실행해 31을 확인합니다. `int targetValue = arr[0];`을 `int targetValue = 0;`으로 바꾸고 배열을 `{-5, -2, -9}`로 바꿔 실행합니다. 배열에 없는 값이 결과로 나오는 것을 적은 뒤 되돌립니다.

### 3-5. 최댓값을 최솟값으로
`MaxValue`를 최솟값을 찾는 코드로 고칩니다. **비교 연산자 하나만** 바꾸면 됩니다.

### 3-6. 조건 하나로 홀수 합이 짝수 합이 된다
`SumOfOdds`를 실행해 25를 확인합니다. 조건을 `i % 2 == 0`으로 바꿔 짝수 합 30이 나오는지 확인합니다.

### 3-7. 경계를 한 칸 넘기면
`ArraySum`(for문 버전)의 조건식을 `i <= arr.length`로 바꿔 실행합니다. 나온 예외 이름과 메시지(`Index 4 out of bounds for length 4` 형태)를 **원문 그대로** 적고, 컴파일은 통과했다는 점도 함께 적습니다. 확인 후 `i < arr.length`로 되돌립니다.

### 3-8. 되돌린 코드는 늘려도 괜찮은가
3-7에서 되돌린 코드에서 배열을 `{2, 1, 7, 9, 5, 3}`으로 늘려도 예외 없이 도는지 확인합니다.

## 스스로 점검

- 합계의 시작값 0, 곱셈의 시작값 1을 "그 연산에서 결과를 바꾸지 않는 값"으로 설명할 수 있다.
- 3-3에서 4와 4.75가 갈린 이유를 int 나눗셈으로 설명할 수 있다.
- 3-7의 예외가 컴파일 오류가 아니라 **실행 중** 오류인 이유를 안다.

## 막혔을 때

- 결과가 항상 0이면 곱셈 누적의 시작값이 0은 아닌지 확인하세요.
- `ArrayIndexOutOfBoundsException`이 보이면, 조건식이 `<=`인지 `<`인지부터 확인하세요.
