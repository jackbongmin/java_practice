# 2일차 1교시 실습 — 배열 개념과 메모리 구조

## 이번 시간에 할 일

- 배열 **이름**을 출력한 것과 배열 **요소**를 출력한 것이 왜 다르게 보이는지 눈으로 확인합니다.
- `new`가 칸을 만들 때 기본값으로 채운다는 것을, 숫자 배열과 객체 배열로 나누어 관찰합니다.

## 실습 파일

- `chapter04/ArrayDefineAndPrint.java` / `ArrayDefineAndPrint2.java` / `ArrayDefineAndPrint3.java`
- `chapter04/TwoDimArray.java` / `TwoDimArrSetValue.java`
- `chapter04/ReferenceTypeArray.java` (+ `Student.java`)

## 미션

### 1-1. 이름과 요소는 다른 것을 보여 준다
`ArrayDefineAndPrint` → `ArrayDefineAndPrint2` → `ArrayDefineAndPrint3`을 순서대로 실행하고 세 출력을 나란히 적습니다. 세 코드의 차이가 `println`에 넘긴 값 하나뿐임을 확인합니다.
→ `[I@1b6d3586`처럼 보이는 출력이 왜 나오는지 "배열 이름은 객체를 가리킨다"로 한 줄 설명합니다.

### 1-2. 기본값은 타입마다 다르다
`ArrayDefineAndPrint3`의 `int[]`를 `boolean[]`으로, 그다음 `String[]`으로 바꿔 각각 실행합니다. 나온 기본값을 타입별로 표에 적습니다. (숫자는 0, boolean은 false, 객체는 무엇인가요?)

### 1-3. 꺼내 온 1차원 배열에 값을 넣으면 어디가 바뀌나
`TwoDimArray`에서 `arr0[0] = 1;`을 `arr0[2] = 1;`로 바꿉니다. **실행 전에** 세 줄의 출력을 예측해 적고, 실행해 비교합니다.

### 1-4. 앞 인덱스와 뒤 인덱스 중 무엇이 행인가
`TwoDimArrSetValue`에서 `arr[0][2] = 3;`을 `arr[2][0] = 3;`으로 바꿉니다. **실행 전에** 출력이 어떻게 바뀔지 예측해 적고, 실행해 비교합니다.
→ 앞 인덱스와 뒤 인덱스 중 무엇이 행인지 한 문장으로 정리합니다.

### 1-5. 값을 넣기 전에는 무엇이 들어 있나
`ReferenceTypeArray`를 실행하면 아무것도 안 찍힙니다. 마지막 줄에 다음을 추가해 값이 들어갔는지 확인합니다.

```java
System.out.println(students[0].name);
```

### 1-6. 칸은 있는데 객체가 없을 때
1-5에서 `students[1] = new Student();` 한 줄만 주석 처리하고, 아래에 다음을 추가해 실행합니다.

```java
System.out.println(students[1].name);
```

나온 **예외 이름과 메시지를 원문 그대로** 적은 뒤 주석을 되돌립니다.

## 스스로 점검

- `int` 배열의 기본값 0과 객체 배열의 기본값 null이 왜 다른지 설명할 수 있다.
- 1-6의 `NullPointerException`이 "칸은 있지만 그 칸을 채울 객체가 아직 없다"는 상태임을 안다.

## 막혔을 때

- 배열 요소를 찍었는데 `[I@...`가 나오면, 요소가 아니라 배열 이름을 넘긴 것은 아닌지 확인하세요.
