# 2일차 7교시 실습 — break, continue와 중첩 반복

## 이번 시간에 할 일

- `break`(반복을 끝냄)와 `continue`(다음 반복으로 건너뜀)의 차이를, 같은 코드에서 한 단어만 바꿔 확인합니다.
- 중첩 반복에서 바깥 한 번에 안쪽 전체가 도는 구조와, 안쪽 break가 **안쪽만** 끊는다는 것을 관찰합니다.
- 2교시에서 손으로 대입했던 2차원 배열을 중첩 for로 채웁니다.

## 미션

### 7-1. break를 continue로 바꾸면
`ForBreak`을 실행해 `0 1 2 3 4`를 확인합니다. `break;`만 `continue;`로 바꿔 **실행 전에** 출력을 예측하고 실행해 `0 1 2 3 4 6 7 8 9`와 맞춰 봅니다. continue가 5만 건너뛰고 6부터 잇는 이유를 적습니다.

### 7-2. continue는 증감식을 건너뛰지 않는다
7-1의 continue 버전에서 5 다음이 6인 것을 근거로, for의 증감식 `i++`가 정상 실행되는지 확인합니다. continue가 무엇을 건너뛰고 무엇은 건너뛰지 않는지 한 줄로 적습니다.

### 7-3. 고르기와 걸러내기는 조건이 반대다
`SumOfOdds`를 실행해 25를 확인합니다. `if (i % 2 != 0) { answer += i; }` 방식을, `if (i % 2 == 0) { continue; }` 다음에 `answer += i;`를 두는 방식으로 다시 써서 같은 25가 나오게 합니다. 두 조건이 서로 반대인 이유를 적습니다.

### 7-4. 답을 찾으면 멈춘다
`IsPrimeBreak`을 실행해 992가 소수가 아님을 확인합니다. `break` 앞에 `System.out.println(i);`를 넣어 몇 번째 i에서 멈추는지 확인한 뒤 지웁니다. `num`을 997로 바꾸면 반복이 몇 번 도는지, break가 실행되는지 예측하고 확인합니다.

### 7-5. break를 지우면 입력 루프가 어떻게 되나
`WhileLoopWithLimit`을 실행하고 0을 입력해 즉시 종료됨을 확인합니다. `break;`를 지우고 0을 입력하면 어떻게 되는지 예측한 뒤 실행합니다. (0을 입력해도 종료되지 않고 10회를 다 쓸 때까지 계속됨을 확인) 확인 후 되돌립니다.

### 7-6. 구분선을 안쪽으로 옮기면
`MultiplicationTableStep`을 실행해 27줄과 구분선 3개를 확인합니다. 구분선 `println("---")`을 안쪽 for **안으로** 옮기면 몇 번 찍힐지 예측(27)하고 실행해 맞춘 뒤 되돌립니다.

### 7-7. 손 대입을 중첩 for로 바꾼다
`int[][] arr = new int[5][5];`를 중첩 for로 순회하며 `arr[i][k] = (i + k) % 2;`를 채우고 행 단위로 출력하는 코드를 새로 작성합니다. 완성 후 `TwoDimArrFillColumn`(손으로 대입한 5줄)과 비교해 반복이 대체한 부분을 적습니다.

### 7-8. 안쪽 break는 바깥을 못 멈춘다
7-7의 안쪽 for에 `if (arr[i][k] == 1) break;`를 넣어 봅니다. 바깥 반복은 계속 도는 것을 출력으로 확인합니다. 바깥까지 멈추려면 무엇이 더 필요한지(플래그 변수) 한 줄로 적습니다.

## 스스로 점검

- 7-1 · 7-2에서 break와 continue의 이동 지점 차이를 출력으로 설명할 수 있다.
- 7-4에서 997은 나누어떨어지지 않아 break가 실행되지 않고 끝까지 돈다는 것을 안다.
- 7-8에서 안쪽 break가 바깥 반복을 멈추지 못하는 이유를 중첩 구조로 설명할 수 있다.

## 막혔을 때

- 중첩 반복에서 열의 길이는 `arr.length`가 아니라 `arr[i].length`입니다.
- break를 넣었는데도 반복이 계속 돌면, 지금 끊은 것이 안쪽 for인지 바깥 for인지 확인하세요.
