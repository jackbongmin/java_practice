# 1일차 6교시 실습 — 변수와 타입

## 이번 시간에 할 일

- **선언 · 초기화 · 재할당**의 차이와 `final`의 제약을 컴파일 결과로 확인합니다.
- 원시 타입 변수와 참조 타입 변수가 **담고 있는 것**이 다르다는 것을 관찰합니다.

## 실습 파일

- `chapter03/DefineAVariable.java`
- `chapter03/DefineAndInitialize.java`
- `chapter03/ConstantEx.java` / `ConstantEx2.java`
- `chapter03/SpaceInvadersMemberVariable.java` / `SpaceInvaderMemberVariableTest.java`
- `chapter03/Point.java` / `PointTest.java`
- `chapter03/Factory.java` / `FactoryTest.java`

## 미션

### 6-1. 선언만 하고 값을 안 넣으면
`DefineAVariable`을 실행합니다. 그 다음 `iVal = 1;` 줄을 **지우고** 컴파일해 오류 메시지를 기록한 뒤 되돌립니다.
→ `DefineAndInitialize`와 비교합니다. 이쪽은 선언과 초기화를 **한 줄에** 했습니다. 두 코드가 결국 같은 일을 하는지 한 줄로 적습니다.

### 6-2. `final`은 무엇을 막는가
`ConstantEx`를 실행해 정상 동작을 확인합니다. 그 다음 `ConstantEx2`에서 주석 처리된 줄을 살립니다.

```java
IVAL = 2; // 주석 해제
```

컴파일 오류 메시지를 기록하고, `final`이 막는 것이 **무엇인지** 한 줄로 씁니다. (값이 틀려서가 아닙니다.)

### 6-3. 메서드 호출이 값을 바꾼다
`SpaceInvaderMemberVariableTest`에 마지막 줄로 다음을 추가합니다.

```java
System.out.println(simv.location);
```

**실행 전에** 최종 `location` 값을 예측해 적고, 실행해 확인합니다.

### 6-4. 순서를 바꾸면 결과가 바뀌는가
6-3에서 `moveLeft()` / `moveRight()` **호출 순서만** 바꿉니다. 최종 값이 달라질지 먼저 예측한 뒤 실행해 확인합니다. 예측이 맞았다면 그 근거도 적습니다.

### 6-5. 멤버 변수는 왜 초기화 없이도 되는가
`SpaceInvadersMemberVariable`의 `int location;`은 **초기화가 없는데도** 실행됩니다. 6-1에서 본 지역 변수 오류와 비교해, 두 규칙이 어떻게 다른지 적습니다.

### 6-6. 두 변수가 같은 대상을 가리킬 때
`PointTest`를 실행합니다. 그 다음 아래 두 줄을 추가합니다.

```java
Point point2 = point;
point2.x = 99;
System.out.println("point.x = " + point.x);
```

**실행 전에** `point.x`가 10일지 99일지 예측해 적고, 실행해 확인합니다.
→ 결과를 참조 타입 개념으로 설명하고, 두 변수와 하나의 인스턴스 관계를 **그림으로** 그려 봅니다.

### 6-7. 값은 인스턴스마다 따로 유지된다
`Factory.java`를 엽니다. 멤버 변수가 넷(`name` · `enabled` · `address` · `machines`)인데
어디에도 값이 없습니다. `FactoryTest`를 실행해 `factory1`에 값이 채워지는 것을 확인합니다.

이제 `main` 끝에 아래를 추가합니다.

```java
Factory factory2 = new Factory();
System.out.println("factory2.machines = " + factory2.machines);
System.out.println("factory2.enabled = " + factory2.enabled);
System.out.println("factory2.name = " + factory2.name);
```

**실행 전에** 세 값을 예측해 적으세요. `factory1`에 넣은 값이 `factory2`에도 보일까요?
→ 실행해 확인하고, 6-5의 멤버 변수 기본값 규칙(`int`는 0, `boolean`은 false, 참조 타입은 null)과
연결해 한 줄로 적습니다. 확인 후 추가한 줄은 되돌립니다.

## 스스로 점검

- 6-1(지역 변수)과 6-5(멤버 변수)의 초기화 규칙 차이를 설명할 수 있다.
- 6-2의 오류가 "값이 틀려서"가 아니라 "**재할당이 금지돼서**"임을 안다.
- 6-6에서 `point.x`가 99가 된 이유를 "두 변수가 같은 대상을 가리킨다"로 설명할 수 있다.
- 6-7에서 `factory2`가 `factory1`의 값을 물려받지 않는 이유를 인스턴스 단위로 설명할 수 있다.

## 막혔을 때

- 컴파일 오류 메시지에 `might not have been initialized`가 보이면, 그 변수는 **선언만 되고 값이 들어간 적이 없다**는 뜻입니다.
- 실행했는데 아무것도 안 찍히면, 출력 문장을 아예 넣지 않은 것은 아닌지 확인하세요(3교시 1번과 같은 상황).

## 제출 결과물

- 6-1 · 6-2의 컴파일 오류 메시지 두 건
- 6-3 ~ 6-4의 예측값과 실제 값을 나란히 적은 표
- 6-6의 실행 결과와 참조 관계를 그린 손그림(또는 도식) 한 장
- 6-7의 예측값과 실제 값(`0` · `false` · `null`) 대조
