# 5일차 2교시 실습 — 제네릭 인터페이스와 컬렉션

## 이번 시간에 할 일

- 같은 인터페이스가 타입 인수에 따라 다른 연산이 되는 것을 실행 결과로 확인합니다.
- `List<T>`와 `Map<K,V>`에서 타입 자리가 저장·조회를 어떻게 묶는지 직접 출력해 봅니다.

## 실습 파일

- `chapter11/GenericInterface.java` · `FloatGeneric.java` · `StringGeneric.java` · `GenericInterfaceTest.java`
- `chapter11/GenericInterfaceTwoTypes.java` · `GenericTwoTypesFlIn.java` · `GenericTwoTypesTest.java`
- `chapter11/ListEx.java` · `MapEx.java`

## 미션

### 2-1. 같은 calculate, 다른 동작
`GenericInterfaceTest`의 출력 두 줄을 실행 전에 예측해 적고 실행합니다. 같은 `calculate()`가 한 번은 덧셈, 한 번은 문자열 연결이 된 근거를 각 구현 클래스(`FloatGeneric`, `StringGeneric`)에서 찾습니다.

### 2-2. 타입이 안 맞으면 막힌다
`GenericInterfaceTest`에 `gis.calculate("hello", 1);` 을 추가해 컴파일 오류를 확인하고 메시지를 기록한 뒤 지웁니다.

### 2-3. 두 타입 파라미터의 역할
`GenericTwoTypesTest`의 결과를 예측한 뒤 실행합니다. `GenericTwoTypesFlIn`의 `(float)` 캐스팅을 지우고 다시 실행해 결과가 어떻게 바뀌는지 기록하고 복원합니다. `T`가 결과, `S`가 입력임을 코드로 확인합니다.

### 2-4. List는 인덱스로 묶는다
`ListEx`를 실행해 두 줄의 출력을 확인합니다. `iList.add("30");` 을 추가해 컴파일 오류를 확인하고 지웁니다.

### 2-5. Map은 키로 값을 꺼낸다
`MapEx`를 실행하면 **아무것도 출력되지 않습니다.** 이유를 먼저 적고, 다음을 추가해 값을 꺼내 출력합니다.

```java
System.out.println(ssMap.get("name"));
int a = siMap.get("A");
System.out.println(a);
```

`siMap.get("A")` 에 형 변환이 필요 없는 이유를 `Map<K,V>`의 `V` 자리로 설명합니다.

### 2-6. 없는 키를 꺼내면
`MapEx`에서 `siMap.get("C")` 를 `int` 변수에 담아 출력하면 무슨 일이 일어나는지 예측하고 실행해 확인합니다. 관찰한 예외 이름을 기록합니다. 확인 후 추가한 코드를 되돌립니다.

## 스스로 점검

- 인터페이스의 `T` 하나가 매개변수와 반환 타입을 동시에 묶는 위치를 짚을 수 있다.
- `List`는 인덱스로, `Map`은 키로 값을 찾는다는 차이를 자기 코드로 설명할 수 있다.
- 2-6의 예외가 왜 `int` 변수 대입에서 나는지 설명할 수 있다.

## 막혔을 때

- `MapEx`가 아무것도 출력하지 않는 것은 오류가 아닙니다. `get()`으로 꺼내 출력하는 코드가 없기 때문입니다.
- 없는 키를 `int`에 담을 때 나는 예외는 값이 `null`이기 때문입니다(자동 언박싱).

## 제출 결과물

- 2-2·2-4에서 기록한 컴파일 오류 메시지 원문
- 2-3의 캐스팅 유무에 따른 실행 결과 두 개
- 값을 출력하도록 수정한 `MapEx` 코드 조각과 실행 결과 캡처
- 2-6에서 관찰한 예외 이름과 그 원인 한 문장
