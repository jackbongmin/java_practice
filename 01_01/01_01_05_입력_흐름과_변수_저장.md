# 1일차 5교시 실습 — 입력 흐름과 변수 저장

## 이번 시간에 할 일

- 세 가지 입력 API에 **각각에 맞는 입력**을 넣어(4교시 4-6 예측표의 「넣을 입력」 열), **읽는 단위**와 **반환 타입**이 어떻게 다른지 확인합니다. 입력 형태가 API마다 다른 것 자체가 읽는 단위가 다르다는 증거입니다.
- 입력값을 **변수에 저장해야** 다시 쓸 수 있다는 것을 코드 수정으로 확인합니다.

## 미션

### 5-1. 한 글자만 읽는 API
`JavaInputTest`를 실행해 `1`을 입력하고 출력값을 기록합니다. 예측표와 다르다면 **왜 그 숫자가 나왔는지** 적습니다. (힌트: 읽은 것은 문자인가 숫자인가?)

### 5-2. 한 줄씩 읽는 API
`BufferedReaderExTest`를 실행해 `12`와 `34`를 **각각 한 줄씩** 입력하고 결과를 기록합니다.

### 5-3. 더했는데 46이 아니라면
`BufferedReaderTwoNumbersTest`를 실행해 같은 값을 입력합니다. 출력이 **46인지 1234인지** 확인하고, 그 결과가 나온 이유를 `readLine()`의 **반환 타입**으로 설명합니다.

### 5-4. 한 곳만 바뀌었는데 결과가 달라진다
`ScannerExTest`(실행하면 `ScannerEx`의 `sc.next()`가 돕니다)와 `ScannerExInt`(내부는 `sc.nextInt()`)를
각각 실행해 `12 34`를 입력하고, 두 결과를 나란히 적습니다.

이제 `chapter02/ScannerEx.java`와 `chapter03/ScannerExInt.java`를 나란히 열어 비교합니다.

```
diff chapter02/ScannerEx.java chapter03/ScannerExInt.java
```

- 다른 곳은 모두 몇 군데입니까? → ____군데
- 그중 **출력 결과를 바꾼 것은 어느 하나**입니까? → __________
- 나머지는 왜 결과에 영향이 없습니까? (패키지·클래스명·주석·`main` 유무) → __________

> 「한 줄만 달라도 결과가 달라진다」와 「여러 줄이 달라도 결과에는 한 줄만 영향을 준다」는
> 서로 다른 이야기입니다. **무엇이 결과를 바꾸는지 고르는 것**이 이 문항입니다.

### 5-5. 안내문의 위치
`ScannerWithGuide2Test`를 실행합니다. 그 다음 `ScannerWithGuide2`의

```java
System.out.print("첫 번째 숫자:");
```

를 `println`으로 바꿔 다시 실행하고, **입력 커서 위치**가 어떻게 달라지는지 캡처 두 장으로 비교합니다. 확인 후 되돌립니다.

### 5-6. 저장했기 때문에 다시 쓸 수 있다
`StoreValueAndPrint`를 실행해 두 값을 입력합니다. 이어서 기존 `printf` 아래에 곱셈 결과를 출력하는 줄을 추가합니다.

```java
System.out.printf("%d과(와) %d의 곱은 %d입니다.%n", first, second, first * second);
```

→ **입력을 다시 받지 않았는데도** 값을 쓸 수 있는 이유를 한 줄로 적습니다.

### 5-7. (확장) 사칙연산을 변수에 담아 정돈해 출력하기
5-6의 `StoreValueAndPrint`를 이어서 확장합니다. 덧셈 · 뺄셈 · 곱셈 · **몫** · **나머지**를 각각 **별도의 변수에 저장**한 뒤, `printf`로 줄을 맞춰 출력합니다.

```java
int sum = first + second;
int diff = first - second;
// ... 곱셈, 몫(/), 나머지(%) 변수도 같은 방식으로 선언
System.out.printf("%-6s %d %n", "합",  sum);
System.out.printf("%-6s %d %n", "차",  diff);
```

- 몫과 나머지를 계산할 때 두 번째 입력값으로 `0`을 넣으면 어떻게 될지 **예측한 뒤** 실행해 확인합니다. 발생한 예외 이름을 기록하세요.

### 5-8. (확장) 여러 타입을 순서대로 입력받기
`ScannerEx`는 지금 문자열만 받습니다. 이를 확장해 **나이(정수)** · **키(실수)** · **학생 여부(참/거짓)** 를 차례로 입력받아 출력하도록 고칩니다.

- 각 값을 받기 **전에** `System.out.print("나이를 입력하세요: ");` 같은 안내 문구를 출력해, 5-5에서 본 것처럼 입력 흐름이 자연스럽게 이어지도록 합니다.
- 정수는 `nextInt()`, 실수는 `nextDouble()`, 참/거짓은 `nextBoolean()`으로 받습니다.
- 실행 후 학생 여부에 `yes`를 입력하면 어떻게 되는지도 확인하고 예외 이름을 적습니다.

## 스스로 점검

- 4교시 예측표 세 칸에 실제 결과를 채우고 ○/× 를 표시했다.
- 5-3의 결과를 "`readLine()`의 반환 타입이 `String`이므로"로 설명할 수 있다.
- 5-6에서 입력 API를 다시 호출하지 않아도 됐던 것이 **변수** 덕분임을 설명할 수 있다.

## 막혔을 때

- 프로그램이 멈춘 것 같으면 **입력 대기 중**입니다. 콘솔 창을 클릭하고 값을 입력한 뒤 엔터를 누르세요.
- `nextInt()`에 문자를 넣으면 `InputMismatchException`이 납니다. 오류가 아니라 **타입 검사가 작동한 것**입니다.
