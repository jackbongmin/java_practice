## 미션

### 8-1. 결과가 어디에 남는가
`StringConcat`과 `StringFormat`을 각각 실행하고 **출력이 같은지** 확인합니다.
→ 두 코드에서 "만들어진 문자열이 **어디에 담기는가**"의 차이를 한 줄로 적습니다.

### 8-2. 찾았다 / 못 찾았다를 표현하는 두 방식
`ContainsExample`과 `IndexOfExample`을 실행하고, 여섯 줄의 출력을 표로 정리합니다.

| 문자열 | contains 결과 | indexOf 결과 |
|--------|--------------|-------------|
| 성남 상록 이비인후과 | | |
| 분당 화이트 치과 | | |
| 영광 의원 | | |

→ `indexOf`가 **-1**을 돌려준 줄을 표시하고 그 의미를 적습니다. 두 메서드의 **반환 타입**은 각각 무엇인가요?

### 8-3. 인덱스는 어디서부터 세는가
`HelloSubstring`, `KoreaSubstringFront` / `Center` / `End`를 모두 실행해 결과를 **인덱스 축 위에** 정리합니다.

```
"대한민국"
 0   1   2   3
```

이어서 `KoreaSubstringFront`에서 다음 두 가지를 추가로 시도하고 결과를 기록합니다.

```java
System.out.println(str.substring(0, 4));
System.out.println(str.substring(4));   // 무엇이 출력되는가? 오류인가?
```

### 8-4. `==` 와 `equals()`
`StringEqualsSubstring`을 실행합니다. 그 다음

```java
System.out.println(str1.substring(0, 1) == str2);   // equals → ==
```

로 바꿔 실행하고 결과가 달라지는지 확인한 뒤 되돌립니다.
→ 왜 그런지를 **참조 타입** 개념으로 적습니다. 문자열의 **내용**을 비교하려면 무엇을 써야 하나요?

### 8-5. 나눈 조각을 더하면
`StringSplit`을 실행해 6줄의 출력을 확인합니다.

1. 구분자를 `str.split(",")`로 바꾸면 결과가 어떻게 될지 **예측한 뒤** 실행합니다. (힌트: 이 문자열에 쉼표가 있나요? `strArr[1]`은 존재할까요?) 발생한 예외가 있으면 이름을 기록하고 **원래대로 되돌립니다.**
2. 되돌린 상태에서 아래 줄을 추가합니다.

```java
System.out.println(strArr[0] + strArr[1]);
```

**실행 전에** 결과가 `13`일지 `103`일지 예측하고, 실행해 확인합니다. 그 결과가 나온 이유를 **타입**으로 설명합니다.

### 8-6. 서식은 값을 바꾸지 않는다 (1일차 마무리)
`ScannerFloat`을 실행해 세 값을 입력하고 평균을 확인합니다. 그 다음 `%.1f`를 `%f`로 바꿔 다시 실행합니다.
→ **계산 결과가 바뀐 것**인지 **표시만 바뀐 것**인지 판정하고, 근거를 적습니다. (4교시 4-4와 같은 이야기입니다.)

## 스스로 점검

- 8-2에서 `contains`(false)와 `indexOf`(-1)의 **반환 타입 차이**를 설명할 수 있다.
- 8-4에서 문자열 내용 비교에 `equals()`를 써야 하는 이유를 말할 수 있다.
- 8-5의 결과 `103`이 **문자열 연결** 때문임을 타입으로 설명할 수 있다.
- 8-6에서 서식이 값을 바꾸지 않는다는 것을 확인했다.

## 막혔을 때

- `StringIndexOutOfBoundsException` / `ArrayIndexOutOfBoundsException`은 **없는 자리를 꺼내려 했다**는 뜻입니다. 인덱스가 0부터 시작한다는 점을 다시 확인하세요.
- 코드를 바꿔 본 파일은 **모두 원래대로 되돌린 뒤** 제출하세요.
