## 미션

### 8-1. 세 변수가 열 개가 되면
`ArraySplitNextInt`에 `12 34 56`을 입력해 합 102를 확인합니다. 입력이 열 개로 늘면 어떤 코드가 반복되는지 보고, 세 변수 대신 배열+for로 바꾸면 무엇이 줄어드는지 한 문장으로 적습니다. (구현은 8-3에서 합니다.)

### 8-2. 문자열 연결과 정수 합
`ArraySplitNextLine`에 `12 34 56`을 입력하면 `123456`이 나옵니다. `split`의 결과가 `String[]`이라 `+`가 문자열 연결이 된 것이 원인입니다. `ArraySplitParseInt`처럼 `Integer.parseInt`로 int로 바꾼 뒤 더하도록 고쳐 합 102가 나오게 합니다. (두 파일의 구분자가 공백인지 콤마인지 각각 확인하세요.)

### 8-3. 입력 개수만큼 배열에 담는다
`int n = sc.nextInt();` 다음에 `int[] scores = new int[n];`로 길이를 입력으로 정하고, for로 n개를 입력받아 저장하는 코드를 새로 작성합니다. `AccumulateUntilN`을 참고해, 저장하는 반복과 처리하는 반복이 같은 조건식 `i < scores.length`를 쓰는지 확인합니다.

### 8-4. 한 순회로 합계와 최댓값을 함께
8-3의 `scores`를 대상으로 `sum`과 `max`를 **하나의 for** 안에서 함께 누적하고, 반복이 끝난 뒤 다음 줄로 평균을 계산해 출력합니다.

```java
double avg = (double) sum / scores.length;
```

평균 계산을 반복 **안에** 넣으면 어떻게 될지 예측한 뒤 확인합니다.

### 8-5. 두 함정: 초기값과 (double)
8-4에서 `max = scores[0]`으로 시작하고 i를 0부터 도는데 문제가 없는지 확인합니다. 첫 비교가 무엇과 무엇을 비교하는지로 답합니다. `(double)`을 빼면 평균이 정수로 잘리는 것을 실행으로 확인합니다.

### 8-6. 점수를 등급으로
8-3의 `scores`에 대해 각 점수를 90/80/70 기준 if-else if로 A·B·C·F 판정해 출력합니다. 조건 순서를 거꾸로(70부터) 두면 95점이 어떤 등급이 되는지 5교시 결과와 연결해 확인합니다.

### 8-7. 네 도구가 한 화면에
`int[][] grid = new int[3][3];`를 중첩 for로 순회하며 아래를 채우고 바둑판으로 출력합니다.

```java
grid[i][k] = (i + k) % 2 == 0 ? 1 : 0;
```

이 한 코드에 배열(저장)·연산자(`%`, `+`)·조건(삼항)·반복(중첩 for)이 모두 들어 있음을 표로 표시합니다.

## 스스로 점검

- 8-4에서 평균을 반복 밖에서 한 번만 계산해야 하는 이유를 설명할 수 있다.
- 8-5에서 `(double)` 유무로 4.x와 4가 갈리는 것을 int 나눗셈으로 설명할 수 있다.
- 8-7에서 오늘의 네 도구가 각각 어느 줄에 대응하는지 짚을 수 있다.

## 막혔을 때

- 합이 `123456`처럼 이어 붙으면, 아직 문자열이라 `+`가 연결로 동작한 것입니다. `Integer.parseInt`로 int로 바꾸세요.
- 평균이 소수점 없이 나오면 `int / int` 나눗셈입니다. 나누기 전에 `(double)`을 붙이세요.
