# 1일차 7교시 실습 — 타입 체계와 String

## 이번 시간에 할 일

- 정수 · 실수 · 논리 타입의 **제약**을 컴파일 오류와 출력 차이로 확인합니다.
- 타입 검사가 잘못된 값을 **실행되기 전에** 막아 준다는 것을 직접 겪습니다.

## 실습 파일

- `chapter03/PrimitiveTypeByte.java`
- `chapter03/BooleanTypeResult.java`

## 미션

### 7-1. 한 칸을 넘기면
`PrimitiveTypeByte`를 실행합니다. 그 다음

```java
byte bValTo = 128;   // 127 → 128
```

로 바꿔 컴파일하고 오류 메시지를 기록합니다. 이어서 타입만 `int`로 바꾸면 통과하는지 확인한 뒤 **원래대로 되돌립니다.**
→ 값은 그대로인데 **타입만 바꿨더니** 통과한 이유를 한 줄로 적습니다.

### 7-2. 비교의 결과는 무슨 타입인가
`BooleanTypeResult`를 **실행 전에** 두 줄의 출력을 예측해 적고, 실행해 확인합니다.
그 다음 `1 == 2`를 `1 != 2`로 바꾸면 결과가 어떻게 되는지도 예측 → 확인합니다.

### 7-3. float와 double의 자릿수
`FloatLength`를 실행해 `f1`과 `d1`의 출력 **자릿수**를 비교합니다. 차이가 생긴 이유를 한 줄로 적습니다.

### 7-4. `f`를 빼면 왜 안 되는가
`DefineAFloatAndDouble`의

```java
float f1 = 3.14f;
```

에서 `f`를 지우고 컴파일합니다. 오류 메시지를 기록한 뒤 되돌립니다.
→ 이 오류는 7-1의 오류와 **같은 규칙**입니다. 무엇이 같은지 적습니다.

### 7-5. 형 변환에서 사라지는 것
`NarrowingCasting`을 **실행 전에** `iVal` 값을 예측해 적고, 실행해 확인합니다. 사라진 값이 정확히 무엇인지 적습니다.

### 7-6. 서식과 타입이 어긋나면
`VariableEx`를 실행해 정상 출력을 확인합니다. 그 다음 `%d` 자리에 `sOne`이 넘어가도록 **인수 순서만** 바꿔 실행합니다.

```java
System.out.printf("String:%s Number:%d Float:%f", iOne, sOne, fOne);
```

발생한 **예외 이름**을 기록한 뒤 되돌립니다.
→ 이 오류는 컴파일 때 났나요, 실행 중에 났나요? 7-1 · 7-4와의 차이를 적습니다.

## 스스로 점검

- 7-1과 7-4의 오류가 모두 "타입이 맞지 않아 **컴파일이 막았다**"는 같은 규칙임을 설명할 수 있다.
- 7-6은 컴파일이 아니라 **실행 중**에 났다는 차이를 확인했다.
- `float`와 `double` 중 무엇을 고를지 판단 기준을 한 문장으로 말할 수 있다.

## 막혔을 때

- `incompatible types` / `possible lossy conversion` 메시지는 "넣으려는 값의 타입이 그릇에 안 맞는다"는 뜻입니다.
- `Exception in thread "main" ...`으로 시작하면 **컴파일은 통과했고 실행 중에 터진 것**입니다. 이 구분을 항상 확인하세요.
