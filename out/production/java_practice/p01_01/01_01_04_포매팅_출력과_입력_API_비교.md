## 미션

### 4-1. `\n`이 없으면
`PrintfEx`를 실행합니다. 세 `printf` 중 **마지막 것만** `\n`이 없습니다.

- "반갑습니다."는 앞줄에 **붙어** 나옵니까, 새 줄에서 시작합니까? → __________
- 그렇게 되는 이유를 **앞줄 끝**을 보고 설명하세요 → __________
- 그렇다면 마지막 `\n`이 없어서 생기는 눈에 보이는 차이는 무엇입니까?
  실행이 끝난 뒤 **셸 프롬프트(또는 커서)가 어디에 있는지** 보세요 → __________

> `\n`은 「다음 줄로 넘긴다」입니다. **자기 앞이 아니라 자기 뒤에** 영향을 줍니다.

### 4-2. 값을 하나 빼 본다
`PrintfEx`의 두 번째 `printf`에서 값 하나를 지웁니다.

```java
System.out.printf("안녕하세요, %s(주) %s 님.\n", "리코멘드");   // "홍길동" 삭제
```

실행하면 **예외**가 발생합니다. 예외 이름과 메시지를 기록한 뒤 되돌립니다.
→ 이 오류는 컴파일 때 났나요, 실행 중에 났나요?

### 4-3. `%02d`에서 0을 빼면
`PrintfDate`의 `%02d`를 `%d`로 바꿔 실행하고, 출력 문자열이 어떻게 달라지는지 **바꾸기 전/후를 나란히** 적습니다.

### 4-4. 자릿수는 값을 바꾸지 않는다
`PrintfFloatDigit`을 **실행 전에** 세 줄의 출력을 각각 예측해 적고, 실행해 확인합니다.
그 다음 아래 줄을 추가해 결과를 관찰합니다.

```java
System.out.printf("%.0f\n", 3.389);
```

→ `%.1f`로 `3.4`가 찍혔다고 해서 **저장된 값이 3.4가 된 것은 아닙니다.** 그 근거를 한 줄로 적습니다.

### 4-5. 줄바꿈을 모두 지우면
`PrintfNextLineMultiTable`에서 모든 `\n`을 지우고 실행해, 출력이 **몇 줄**이 되는지 확인한 뒤 되돌립니다.

### 4-6. 다음 교시 예측표 (제출 필수)
세 가지 입력 API가 각각 **무엇을 어떤 타입으로** 돌려줄지 미리 예측해 채웁니다.
정답은 5교시에 실행으로 맞춰 봅니다.

**API마다 넣는 입력이 다릅니다.** 읽는 단위가 다르기 때문입니다 — 한 글자만 읽는 API에 두 수를
주는 것은 의미가 없습니다. 5교시에서 각각 아래 입력을 넣습니다.

| 입력 API | 5교시에 넣을 입력 | 읽는 단위 | 반환 타입 | 예상 결과값 |
|----------|---------------|---------|-----------|------------|
| `InputStreamReader.read()` | `1` | | | |
| `BufferedReader.readLine()` | `12`↵`34` (두 줄) | | | |
| `Scanner.nextInt()` | `12 34` (한 줄) | | | |
