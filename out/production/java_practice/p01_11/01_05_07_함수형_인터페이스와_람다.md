# 5일차 7교시 실습 — 함수형 인터페이스와 람다

## 이번 시간에 할 일

- 함수형 인터페이스가 규칙(매개변수·반환)을 정하고 람다가 동작을 채우는 관계를, 타입을 안 써도 컴파일되는 이유로 설명합니다.
- 매개변수 개수·블록 여부·추상 메서드 개수에 따라 람다의 모양과 성립 여부가 어떻게 달라지는지 직접 확인합니다.

## 실습 파일

- `chapter11/StatementNoArgs.java` · `StatementNoArgsTest.java` · `StatementNoArgsTest2.java` · `StatementNoArgsTest3.java`
- `chapter11/StatementWithArg.java` · `StatementWithArgTest.java`
- `chapter11/StatementWithTwoArgs.java` · `StatementWithTwoArgsTest.java`
- `chapter11/TwoAbstractMethods.java` · `TwoAbstractMethodsTest.java`

## 미션

### 7-1. 같은 타입, 다른 동작
`StatementWithTwoArgsTest`의 두 람다 `(x, y) -> x + y` 와 `(x, y) -> 2 * x + 3 * y` 의 출력을 각각 예측해 적고 실행해 비교합니다. 두 람다가 같은 타입 변수에 담기는 이유를 `StatementWithTwoArgs`의 추상 메서드로 설명합니다.

### 7-2. 타입을 안 써도 컴파일되는 이유
`StatementWithTwoArgsTest`에서 `(x, y)`에 타입을 안 썼는데 컴파일되는 경로를 순서대로 적습니다.

`변수 타입 StatementWithTwoArgs` → `유일한 추상 메서드 int calculate(int, int)` → `(x, y)의 타입은 int`

그다음 한 람다를 `(x, y) -> x + "!"` 로 바꿔 컴파일 오류를 확인하고, 어느 규칙을 어겼는지 기록한 뒤 되돌립니다.

### 7-3. 표현식과 블록의 return 규칙
`StatementNoArgsTest`(표현식형)와 `StatementNoArgsTest3`(블록·return형)를 실행해 둘 다 `20`이 나오는지 확인합니다. `StatementNoArgsTest3`의 블록에서 `return`을 지우면 왜 컴파일이 안 되는지 기록하고 되돌립니다.

### 7-4. 매개변수가 없으면 바깥 값을 쓴다
`StatementNoArgsTest2`를 실행해 `30`을 확인합니다. 매개변수가 없는 람다가 바깥 지역변수 `val`을 쓰는 것을 짚습니다. 람다 대입 다음 줄에 `val = 50;` 을 추가해 컴파일 오류를 확인한 뒤 지우고, 바깥 지역변수가 바뀌지 않아야 하는 이유를 한 문장으로 적습니다.

### 7-5. 인수가 하나면 괄호를 줄인다
`StatementWithArgTest`의 `val -> val + 10` 을 `(val) -> val + 10` 으로 바꿔 실행 결과가 같은지 확인합니다. 인수가 둘일 때 괄호를 빼면 어떻게 될지 예측만 적고 되돌립니다.

### 7-6. 람다는 추상 메서드 하나와만 연결된다
`TwoAbstractMethodsTest`의 주석 처리된 줄 `TwoAbstractMethods twoAbstractMethods = (val) -> true;` 의 주석을 풀어 컴파일 오류를 확인합니다. 추상 메서드가 둘일 때 람다가 어느 메서드 구현인지 정할 수 없다는 점을 메시지와 연결해 기록하고, 다시 주석 처리합니다.

## 스스로 점검

- 타입 없는 람다가 컴파일되는 이유를 "변수 타입 → 추상 메서드 → 매개변수 타입" 순서로 설명할 수 있다.
- 표현식형과 블록형 람다의 `return` 규칙 차이를 7-3으로 보일 수 있다.
- 람다가 함수형 인터페이스(추상 메서드 하나)와만 연결된다는 것을 7-6으로 확인했다.

## 막혔을 때

- `TwoAbstractMethodsTest`는 원래 주석 처리되어 있습니다. 미션을 위해 잠깐 풀고 반드시 되돌립니다.
- 4일차의 `인터페이스 변수 = 구현 객체`와 오늘의 `함수형 인터페이스 변수 = 람다`가 같은 구조임을 떠올리면 이해가 빠릅니다.
