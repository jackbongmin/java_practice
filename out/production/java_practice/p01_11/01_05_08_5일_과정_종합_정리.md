### 8-2. 네 문법을 한 코드에 조립한다
`UserTest`의 `main`을 잠깐 확장하거나 임시 클래스 `Chapter11Review`(확인 후 삭제)를 만들어 아래를 직접 작성합니다. 각 줄 옆에 8-1 표의 어느 행에 해당하는지 주석으로 표시합니다. (`import java.util.*;` 필요)

```java
Map<Role, List<User>> usersByRole = new HashMap<>();   // 제네릭 + enum
usersByRole.put(Role.ADMIN, new ArrayList<>());
usersByRole.get(Role.ADMIN).add(new User("kyeongrok", Role.ADMIN));
StatementWithTwoArgs sum = (x, y) -> x + y;             // 람다
```

### 8-3. 없는 키를 꺼내면 어느 예외가 나는가
8-2에 이어 붙입니다. `usersByRole.get(Role.MANAGER)` 가 무엇을 돌려주고 그래서 어느 예외가 날지 **먼저 예측**한 뒤 실행해 맞춰 봅니다.

```java
try {
    System.out.println(sum.calculate(100, 0));
    System.out.println(100 / usersByRole.get(Role.MANAGER).size());
} catch (NullPointerException e) {
    System.out.println("등록된 매니저가 없습니다.");
}
```

### 8-5. 원본으로 되돌린다
8-2·8-3에서 만든 임시 코드나 클래스를 모두 지워 소스 트리를 원본 상태로 복원합니다.

### 8-6. 5일을 한 문장씩 남긴다
1일차부터 5일차까지 각 일차가 "무엇을 통제하게 해 주었는지" 한 문장씩 적습니다. 오늘 배운 것 중 **컴파일러가 대신 검사해 주는 것**과 **내가 직접 판단해야 하는 것**을 각각 하나씩 고릅니다.

## 스스로 점검

- 하나의 코드에서 제네릭·enum·예외·람다가 동시에 쓰이는 자리를 짚을 수 있다.
- `get()`이 없는 키에 `null`을 돌려줘 NullPointerException으로 이어지는 경로를 예측·확인했다.
- 컴파일 시점에 걸리는 실수와 실행 시점에만 드러나는 실패를 각각 예로 들 수 있다.

## 막혔을 때

- `Map.get()`은 없는 키에 예외가 아니라 `null`을 돌려줍니다. 그 `null`에 `.size()`를 부르는 순간 NullPointerException이 납니다.
- 임시로 만든 코드는 반드시 8-5에서 되돌려 원본 소스를 보존합니다.
