# 2일차 2교시 실습 — 인덱스와 길이, 배열 순회

## 이번 시간에 할 일

- 손으로 여러 줄 쓴 코드를 `for` 하나로 줄이고, 고정된 숫자가 **변수 인덱스**로 바뀌는 지점을 확인합니다.
- for의 초기식·조건식·증감식을 바꿔 가며 반복 범위가 어떻게 달라지는지 관찰합니다.

## 미션

### 2-1. 줄 수가 배열 크기를 따라 늘어나는가
`TenxTen`과 `TenxTenFor`를 실행해 출력이 같은지 확인합니다. 두 소스의 줄 수를 세어 적고, 배열을 `new int[20][20]`으로 바꿀 때 각각 몇 줄을 고쳐야 하는지 적습니다.

### 2-2. printf 네 줄을 for 하나로
`ArrayDefineAndPrint4`의 `printf` 네 개를 for문 하나로 바꿔 같은 출력을 만듭니다. 조건식에 `4` 대신 `iArr.length`를 씁니다.

### 2-3. 배열만 늘려도 되는 반복
`ArraySum`의 합산 네 줄을 for문으로 바꿉니다. 그다음 배열을 `{2, 1, 7, 9, 5, 3}`으로 늘리고, **반복문은 고치지 않은 채** 실행해 27이 나오는지 확인합니다.
→ 반복문을 안 고쳤는데 맞은 이유를 `arr.length`로 설명합니다.

### 2-4. for의 세 자리를 바꿔 본다
`ForLoopForward` / `ForLoopForward1To10` / `ForLoopForwardStep` / `ForLoopReverse` / `ForLoopUntil`을 실행하고, 초기식·조건식·증감식·출력 범위를 한 표로 정리합니다. 이어서 `ForLoopUntil`의 `i * i <= 50`을 `i * i < 50`으로 바꾸면 출력이 어떻게 달라질지 예측한 뒤 실행해 확인합니다.

### 2-5. for-each로는 못 하는 것
`ForEachExample`의 for-each를 일반 for문으로 바꿔 같은 출력을 만듭니다. 그다음 "인덱스가 짝수인 칸만 출력"으로 요구가 바뀌면 for-each와 일반 for 중 어느 쪽이 필요한지 코드로 답합니다.

### 2-6. 행 출력을 for로 묶는다
`TwoDimArrFillRow`와 `TwoDimArrFillColumn`을 실행해 출력 모양을 비교합니다. `TwoDimArrFillRow`의 `println` 다섯 줄을 for문 하나로 바꿔 같은 출력을 만듭니다. (대입 다섯 줄은 그대로 둡니다 — 7교시에 중첩 반복으로 묶습니다.)

### 2-7. 길이가 짝수일 때 가운데는 어디인가
`PivotIdx`를 실행합니다. `arr2`(길이 4)의 pivot이 2로 나온 이유를 **정수 나눗셈**으로 설명해 적습니다.

### 2-8. 자리를 맞바꾸는데 값이 같아졌다
`Swap`에서 `int temp` 줄을 지우고 `arr[0] = arr[1]; arr[1] = arr[0];`으로 바꿔 실행합니다. 결과를 적고, 두 값이 같아진 이유를 대입 순서로 설명한 뒤 원래대로 되돌립니다.

## 스스로 점검

- 2-1에서 "코드 줄 수가 배열 크기에 비례하는가"로 손 코드와 for를 비교할 수 있다.
- 2-3에서 배열만 바꿨는데 결과가 맞은 이유를 설명할 수 있다.
- 2-8에서 값이 둘 다 같아진 이유를 대입 순서로 설명할 수 있다.

## 막혔을 때

- 조건식에 배열 크기를 숫자로 박아 두면, 배열을 늘렸을 때 반복이 끝까지 돌지 않습니다. `arr.length`를 쓰세요.
- for를 for-each로 바꿨는데 인덱스가 필요해지면, for-each에는 인덱스 변수가 없다는 점을 떠올리세요.
